# Loom：脚本优先架构与迁移方案

状态：核心脚本路径、TCP/gRPC、生成器及网络限额已落地，旧 Go 宿主已删除。下文保留迁移设计背景；当前 API 与未覆盖边界见协议说明。运行方式和已验证能力以 README、framework.md 与 runtime-requirements.md 为准。
核对日期：2026-10-31。

## 1. 项目定位

Origami 是一门兼容 PHP 的语言。Loom 是用这门语言编写的框架，框架规则、业务流程和应用装配优先在脚本域实现，原生能力通过 Origami `std` 调用。

正常开发、测试和部署 Loom 应用，目标只要求已安装的 Origami 运行程序及项目脚本和依赖，不要求安装 Go、检出 Origami 源码或维护 `go.work`。构建 Origami 自身时使用 Go，属于语言运行时的开发流程。

PHP 兼容语法可以继续使用 `.php` 文件；这不承诺 Loom 能在原生 PHP 解释器下运行。Composer 可以承担包管理和自动加载，不应成为执行 `go run` 的包装。不要求为了体现语言定位而统一改成 `.zy` 扩展名。

## 2. 重构前的偏差与源码依据（以下路径已删除）

- `composer.json` 的 start、loom、test、build 都依赖 Go；`scripts/setup.ps1` 要求 Origami 源码并创建 Go 工作区。
- `runtime/framework/php/services.php` 的 Database、Auth、Queue、Schedule 主要通过 `Loom\host_call` 将操作序列化后交给 Go；脚本只提供门面。
- `runtime/framework/services.go` 包含认证、会话、数据库、队列入库和调度注册规则；`worker.go`、`cron.go`、`migrations.go` 承担任务状态流转、日历计算和迁移编排。
- `runtime/framework/handler.go`、`console.go`、`message.go` 通过 `go:embed` 内嵌框架脚本。脚本框架发布因此与定制宿主构建耦合。
- `runtime/internal/host/` 装配 HTTP、后台任务与多协议服务，并包含 Studio 存储装配和代码生成。通用框架、运行时适配和示例应用的边界混在宿主中。

已有的路由、控制器、视图、ORM 脚本、应用服务和契约测试可继续复用。迁移不是重写 Studio，也不是删除已有功能后重新搭建演示。

## 3. 目标职责

### Origami 运行时与 std

提供执行隔离、并发与取消、网络监听和协议原语、文件与进程、数据库驱动和事务、密码散列与安全随机数、时钟与时区等通用能力。这些能力内部可以由 Go 实现，但对 Loom 暴露稳定的脚本 API。

当脚本缺少所需原语时，先核对标准库已有接口并记录缺口；不为 Loom 专门扩展 Origami。明确的通用语言或标准库错误可以通过独立最小用例验证并修复。不以 `auth.login`、`queue.dispatch` 或 `studio.*` 这样的业务操作作为新标准库接口，也不把现有 Loom Go 业务代码直接搬进 std 来完成表面迁移。

### Loom 脚本框架

负责应用启动和配置、路由与中间件、请求响应适配、依赖注入、视图、ORM 约定、认证与会话策略、迁移历史管理、队列状态与重试、Cron 规则、命令分发及代码生成。

框架直接调用 std；可以提供小型适配器统一异常、返回值和资源释放。避免再造一个 JSON 操作分发桥接层。认证不得自己实现密码算法，而应调用标准库；数据库参数绑定和事务也由标准库执行。

### 应用与部署

`app/`、`routes/`、`resources/`、`database/` 定义 Studio 或其他应用。应用通过 Loom 公共 API 编程，不直接依赖 Go 类型、RequestVM 或宿主注入函数。

HTTP、队列消费和调度可以拥有独立脚本命令，由部署环境管理进程。无需为了保持“一条命令启动所有服务”而把生命周期重新绑定到定制 Go 宿主。开发环境的一键启动可在这些命令稳定后另行提供。

### Go 的边界：仅提供 Origami 运行时

Loom 不设置 Go 兼容层，也不维护新旧宿主双入口。Go 负责实现 Origami 运行时及其标准库；Loom 通过脚本 API 使用这些能力。现有 `runtime/` 中的定制宿主和 Go 框架逻辑是待移除的偏差实现，不是目标架构或迁移方案中的兼容组件。

迁移时提取既有行为和测试用例作为需求依据，将框架规则改写为脚本，删除对应 Go 实现。标准库能力缺口明确记录为未实现，不以保留旧宿主、桥接业务操作或增加临时 Go 适配层解决。分阶段只表示实现顺序，不要求各阶段维持旧入口可运行。

## 4. std 能力核对及待验证项

依据本机 `D:/gitcode.com/origami` 源码检查；这是接口存在性核对，不是运行验证，也不代表某个公开发行版本已包含全部能力。实施前必须固定可复现的 Origami 版本或提交，并运行脚本探针。

- **脚本执行：** `cmd/root.go` 支持 `zy <脚本路径>`，接受 `.php` 与 `.zy`。`zy.go` 装配 std、PHP 兼容函数、HTTP、WebSocket 等模块。需要确认交付二进制与源码版本一致、命令参数和退出码满足 Loom CLI；当前环境未发现 PATH 上的 `origami` 命令，不能直接把它写成已可用的启动方式。
- **数据库：** `std/database/sql/open_func.go` 暴露 `Database\Sql\open`；DB 和 Tx 包含查询、执行和事务方法，`std/database/script_functions.go` 提供连接注册。优先基于这些接口适配现有 `Database::query/execute/batch`。验证绑定参数、NULL、行数据类型、插入 ID、影响行数、回滚、SQLite 锁等待和连接释放。连接注册采用连接管理器，需核查跨请求共享与清理语义，不能把事务对象放入全局共享状态。
- **迁移：** `std/database/migration/load.go` 已注册迁移能力。先核对它与 Loom 版本记录、校验、批次及 down 语义的差异；可复用其符合要求的能力，但不能假定现有 SQL 历史可直接导入。
- **HTTP：** `std/net/http/load.go` 暴露 Server、Request、ResponseWriter、Router 等；`server_run.go` 已实现监听和关闭回调。可作为脚本启动基础，但当前 run 实现未体现 Loom 宿主全部超时配置。请求隔离、请求体限制、并发限制、HEAD、异常映射和取消语义需要逐项验证，必要时在 Origami 增补通用接口。
- **WebSocket：** `std/net/websocket` 已被当前 Loom 复用。迁移脚本装配时仍需保留来源检查、消息大小、连接限额、关闭与取消行为，不能只验证握手成功。
- **密码与令牌：** `std/php/password.go`、`random_bytes.go`、`setcookie.go` 提供 `password_hash`、`password_verify`、`random_bytes`、`hash_equals`。验证旧 bcrypt 密码和会话摘要兼容后，将认证策略移到脚本；不迁移或重写加密算法。
- **进程生命周期与调度：** `std/signal`、`std/channel`、`std/spawn.go` 和时间相关接口是候选原语。需要验证 worker 取消、等待和退出行为；Cron 五字段语义、重试策略及任务租约仍属于 Loom。`std/loop` 当前是集合类，不能因名称而将它当作定时事件循环。
- **TCP/gRPC：** 本次检查没有确认可直接覆盖现有实现的完整脚本接口。`std/protowire` 的编解码能力不等于 gRPC 服务端、反射或传输生命周期。先建立能力清单与探针；有缺口则记录为待实现，不为 Loom 定制协议接口。接口就绪前将对应功能标为待实现，不提供旧协议宿主兼容入口。

## 5. 当前目录与依赖方向

Loom 按具体应用项目开发，内部框架集中在 `framework/`，不拆成独立发布包。当前布局如下；框架源码暂保留模块文件，后续可按模块拆分子目录：

```text
loom.php             脚本命令入口
framework/
  src/                   内部框架模块（Loom 命名空间）
  resources/             内置数据库 schema
  tests/                 框架测试与 fixture
  bootstrap.php          独立框架加载入口
framework/bootstrap/               应用与不同执行入口装配
app/、routes/            应用业务与路由
tests/integration/       项目集成测试
tests/run.php            框架与项目测试的统一入口
```

依赖方向：应用 → Loom 内部框架 → Origami std → 原生实现。命令及测试入口调用 `framework/bootstrap/autoload.php` 返回的加载函数并显式传入应用根目录；框架资源使用自身路径，不根据源码位置推断应用根目录。Loom 脚本源码从文件和自动加载加载，不再以宿主内嵌字符串作为发布入口。请求、事务和作业上下文有明确作用域；服务端生命周期内复用连接池，不共享用户身份和可变请求对象。

## 6. 分阶段迁移与退出条件

### 阶段 0：固定基线并验证原语

记录 Origami 版本、全部脚本入口、待删除的宿主注入函数及现有行为，将现有测试中的业务契约整理为脚本验收用例。用独立脚本验证 std 的数据库事务、HTTP 隔离、标准输入输出、信号和时间接口，并记录通过与缺口。不把源码接口存在当成能力验收，不为维持旧启动方式增加兼容设计。

退出条件：确定可交付的 Origami 执行程序，每个替换点都有已验证接口或明确记录的能力缺口。

### 阶段 1：脚本框架独立加载与 CLI

将 `runtime/framework/php/` 中框架源码迁入 `framework/src/` 并建立 Loom 自动加载。新增脚本 CLI，先承接无服务依赖的命令列表、帮助和生成器；把纯脚本契约改为 Origami 直接执行。移除框架源码内嵌及旧宿主加载路径，只维护脚本入口。

退出条件：不运行 Go 即可加载框架、执行基础命令和脚本契约；缺少自动加载依赖时有明确错误。文档明确标记此阶段仍未迁移的命令。

### 阶段 2：数据库、ORM 与迁移

通过 std 实现数据库适配，保持现有公共 API 返回契约，迁移框架和 Studio 的建表及版本管理。验证历史库兼容与批次回退；业务迁移文件保持不可变。以数据库副本演练升级和回滚，不自动重建真实用户库。

退出条件：ORM 和迁移测试通过，业务数据路径不再调用 `host_call` 的 db 操作；并发与事务行为不弱于基线。

### 阶段 3：HTTP 与认证完整业务链路

用 std HTTP 脚本启动承接路由、请求响应和静态资源；认证及会话策略迁至脚本。迁移请求获取方式，去除该路径对 `request_envelope` 和宿主认证指令的依赖。需要保留 bcrypt 兼容、会话过期与轮换、CSRF、Origin、Cookie 标志、限流和用户资源隔离。

退出条件：使用 Origami 直接运行 HTTP 服务，完成 Studio 注册、登录、项目和任务操作、退出；并发隔离、请求限制和静态资源边界测试通过。WebSocket 独立完成生命周期验收后切换。

### 阶段 4：队列、Cron 与独立后台进程

在脚本实现入队、原子领取、租约、重试和状态更新；将 Cron 解析、时区计算和到期任务生成移入脚本。提供可单次执行的 tick 和常驻 worker/scheduler 命令，便于测试和进程管理。通过 std 使用时间、事务、信号与取消能力。

退出条件：验证至少一次交付、过期租约恢复、租约持有者才可完成任务、最大重试和退避、业务幂等、调度入队与时间推进的原子性，以及时区/DST。不要将新旧调度器同时用于真实数据库来做对照测试；使用隔离副本与固定时间输入。

### 阶段 5：多协议与默认入口切换

在标准库已有接口足以支持时完成 TCP/gRPC 能力验证，把协议路由和生成器编排移至脚本。保留 protobuf、unary RPC、错误映射、反射、压缩及业务文件不被重复生成覆盖的现有契约。

各脚本命令完成后，将对应 Composer start/loom/test 和部署说明改为实际验证过的 Origami 命令；尚未实现的命令明确报错，不回退到 Go 宿主。最终清除 `runtime/` 定制宿主及对 `go:embed`、`host_call`、自定义 envelope 注入的依赖，移除正常安装对 `setup.ps1`、Go 源码路径和 `go.work` 的要求，不设置旧宿主回退窗口。

退出条件：在只有 Origami、项目和依赖、没有 Go 工具链的干净环境完成安装、HTTP/后台/协议运行和测试。构建或打包方式另行验证，不机械地把 `go build` 替换成未经验证的编译命令。

## 7. 验收与后续开发约束

- 默认启动和测试不调用 Go，不要求 Origami 源码检出。
- 框架规则的变更只需修改脚本，不需重新编译定制宿主；脚本是否需要重启以对应进程的加载策略为准，不承诺自动热更新。
- 用户身份、请求属性、事务、队列作业状态不得泄漏到其他执行作用域。
- 外部 API、SQL 数据、迁移历史和现有命令的兼容性由行为测试证明；不能用“已改为脚本”替代功能验收。
- 将原有 Go 集成测试中的业务断言迁为 Origami 脚本测试，随对应宿主代码删除旧测试；运行时与 std 的原生能力测试归 Origami 仓库。测试架构不依赖 Go 兼容宿主。
- 新功能先找 std 原语，再写 Loom 脚本逻辑；发现明确的通用语言或标准库错误时，以独立最小复现修复 Origami；功能缺口先核对；本轮已获授权补齐可独立使用且保留独立测试的通用标准库 API，不增加 Loom 专用接口或业务宿主。

已实现脚本加载、CLI、数据库、认证、迁移、队列、调度、HTTP 与 WebSocket 核心链路；脚本测试和端到端验证通过。正常入口不再依赖 Go，旧宿主及其工具已删除。TCP/gRPC 服务端、生成器、读取前请求体限制、网络超时及并发配额现已补齐；未提供应用 streaming RPC、TLS 终止和统一优雅停机编排。
